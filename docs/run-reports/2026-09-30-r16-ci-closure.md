## Proven causes and minimal fixes

**macOS:** both jobs fail
`backup::tests::pre_restore_safety_copy_keeps_previous_portable_state` at
`src/backup.rs:1226`. SQLite reports `/private/var/folders/...` while the
test's temporary directory uses `/var/folders/...`. These are directory
aliases. The assertion now compares both canonical directories, retaining
the check that the saved JSON equals the complete previous portable state.
No backup runtime implementation, migration or Windows packaging changed.
The corrected existing regression test passes locally; macOS revalidation
is pending.

**Linux:** native packaging creates its archive, then the packaged program
panics at `xkbcommon-dl-0.4.2/src/x11.rs:59`: **Library libxkbcommon-x11.so
could not be loaded.** The locked crate source attempts
`libxkbcommon-x11.so.0` and `.so` dynamically, so passing `ldd` does not
prove its availability. The release workflow now installs
`libxkbcommon-x11-0`; the Linux package README and repository README name
the X11 prerequisite. Ubuntu's [package file list](https://packages.ubuntu.com/jammy/amd64/libxkbcommon-x11-0/filelist)
confirms the library supplied by that package, and Slint documents the
[Winit Linux dependencies](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backend_winit/).
This fixes the project-owned runner prerequisite omission. Native launch
after that change is **not yet proven**; no Linux runner is locally available.
