## R15 — PARTIAL overall; local exit gate passed

### Implemented

- The application acquires an OS file lock on `data/bingee.lock` before opening production SQLite. A concurrent process displays a concise startup error and does not open the database. The file survives a crash, but its lock does not. The production event loop explicitly releases the lock on exit.
- Settings now offers **Check storage** (`quick_check`, `foreign_key_check`, poster count/bytes, 12 MiB decoded RAM budget) and **Clean unused data**. Cleanup runs only on request. A media row is deleted only if no Library, title tracking, episode tracking, watch event or release event references it. Cache cleanup removes Bingee-owned unreferenced posters older than 30 days after last disk read; referenced/recent posters, unknown files and symlinks survive. Poster temporary files older than one hour are removed. Corrupt posters are removed on load. Failure to clean the cache does not make application startup depend on it.
- Backup export writes and syncs a same-folder temporary file. It prefers a no-overwrite hard link; unsupported filesystems use `create_new`, copy and sync. An existing destination is never overwritten. A normal copy failure removes its partial destination; a crash may leave truncated JSON that V1 parsing refuses. Temporary files have identifiable `.bingee-<pid>-<nanoseconds>.tmp` names and are removed on normal completion/error. Arbitrary backup folders are not scanned for deletion.
- Restore still validates before writing, makes a pre-restore portable safety copy, replaces durable data in one IMMEDIATE transaction, checks foreign keys, full integrity and row counts, and rolls back on error. The existing tests force invalid input and import failures; original state remains unchanged.
- File databases use SQLite's default DELETE rollback journal, explicit `synchronous=FULL`, `foreign_keys=ON` and 5,000 ms busy timeout. The pragma test confirms `delete`, `2`, `1`, `5000`. No WAL sidecars are part of normal backup/shutdown. Runtime logs rotate at 1 MiB, retain one previous file, and stop file logging without crashing if rotation fails. No tokens or detailed watch events were added to logs. Release events remain in SQLite; Updates limits display only.

Decision: ADR-0028. Schema remains v5. No runtime crate dependency added.
