## R12 — PASS locally

Home now reads local Continue Watching, Up Next, eight recent watch events, Coming Soon from today through the next 14 days, and a Library summary. Continue Watching reuses tracking progress and orders by latest personal watch, folded title, and local ID. Specials stay outside regular progress. Complete local episodes with incomplete coverage are not called globally complete. Recently watched entries retain rewatches and local presentation time. Provider air dates remain date-only strings.

Calendar has a Monday-first 42-cell month grid, previous/next controls, today and event counts, selected-day events, keyboard navigation, and an incomplete-coverage warning. Both pages load without TMDB or a token. Navigation opens cached media, seasons, episodes, or Discover. Detail timer requests are gated when those pages are shown.

Home uses a fixed number of SQL statements independent of title count; the statement trace test compares empty and 20-series cases and caps the result at ten. Episode, history, and upcoming reads are batched. No `air_date` index or migration was needed. The 1,000-media, 17,550-episode, 10,000-watch-event release fixture measured Home at **30.02 ms** and Calendar month at **7.52 ms** per warm operation (20 runs). Tests cover empty/active/complete/partial series, reactivation, recent history, coming dates, month/year/leap boundaries, Library scope, coverage, date-only semantics, and headless UI. No N+1 regression was found.

## R13 — PASS locally

Backup V1 is UTF-8 JSON with `format`, `format_version`, `created_at`, `application_version`, and typed `data` DTOs. It stores offline media metadata, provider identity triples, Library membership, genres, seasons, episodes, separate detail/season freshness and coverage, movie/episode tracking, ratings, distinct watch and rewatch events, and historical runtime snapshots. R14 extended V1 additively with the automatic-refresh preference and release events. Earlier V1 files without those fields remain importable. Excluded: TMDB token, credential store, binary image cache, logs, temporary files, fixtures, and diagnostics. See `docs/backup-v1.md`.

Restore parses and validates all structure, identities, references, values, dates, and event targets before writing. It replaces durable rows in one SQLite `IMMEDIATE` transaction, checks foreign keys, integrity, and semantic row counts, then commits. Failed import rolls back; no temporary database swap is needed on Windows. Settings requires file selection/validation and a separate confirmation. Before a confirmed restore, Bingee exports current state as a portable safety JSON file beside the live database. Failure to create it blocks replacement. The safety file remains until the user removes it. Export writes/syncs a same-directory temporary file and finalizes with a no-overwrite hard link.

Tests cover empty, Movie-only, TV-only, Movie 603 plus TV 603, removed Library membership with retained personal state, genres, season 0, multiple seasons, partial coverage, stale metadata, ratings, rewatches, watch event ordering/runtime, Statistics equality, invalid/future/truncated formats, bad references and identities, unwritable export, forced mid-import failure, and safety-copy contents. Original state remained unchanged on every restore failure tested. The 1,000-media, 17,550-episode, 10,000-watch-event release fixture measured export **25.1 ms**, serialization **10.2 ms** (6,319,471 bytes), parse plus validation **37.6 ms**, and restore **381.8 ms**. One transaction covers the import.

## R14 — PASS locally

Schema v5 adds one persisted, opt-in automatic-refresh setting and deduplicated release events. The coordinator starts after local UI setup, runs only while Bingee is open, and checks every six hours. It reuses R9 seven-day freshness; each cycle considers at most 50 stale Library titles and 50 stale or partial seasons already downloaded. Changed counts can enqueue additional previously downloaded seasons, with a 150-item queue cap. Unopened seasons are not fetched. One automatic request at a time uses the existing four-worker pool, leaving three workers for interactive work. A 1,000-title fixture confirms bounded selection; the fake-server test measured maximum automatic HTTP concurrency of one.

TMDB 429 pauses for 30 minutes. Offline, timeout, and 5xx pause for 15 minutes. Invalid credentials halt work until credential state changes and trigger the existing Settings credential check. Removed titles are skipped, including if membership changes during flight. Failures keep local data and do not spin. Logging records cycle summaries and failure categories without secrets or personal watch details.

Refreshing a previously downloaded Library season inserts a `new_episode` event only for an episode number absent before the save. A unique key prevents duplicates, and `read_at` survives subsequent metadata refreshes and restart. Updates lists recent events with series, episode, discovery time, air date, and read state; opening an event marks it read and navigates to its episode; Mark all read is available. Home and Calendar reload after metadata changes without restart. Native OS notifications were deferred; no daemon or startup service was added.

Fake-TMDB and local tests cover fresh/stale selection, disabled mode, offline transport, 429, 500, 401, bounded concurrency, one-in-flight suppression, new episode discovery, repeated refresh, restart persistence, read state, and the provider/personal-state boundary. The end-to-end test starts with ten watched episodes, refreshes to eleven, and confirms previous tracking remains, series becomes incomplete, Continue Watching returns, Up Next is E11, Calendar gains E11, and one event exists.
