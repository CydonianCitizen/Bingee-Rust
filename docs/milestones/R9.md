## Implemented

1. **Schema v2** (`database::SCHEMA_V2`, appended; v1 untouched): `media`
   gains `status`, `tagline`, `last_air_date`, `season_count`,
   `episode_count`, `details_fetched_at`; new `genres`, `media_genres`,
   `seasons` (season 0 allowed, series only by composite foreign key, coverage
   columns), `episodes` (key: series + season + episode number; TMDB episode id
   unique per season). No personal columns or tables.
2. **Domain** (`src/metadata.rs`): provider-independent `MediaDetails`
   (+ `TvDetails`), `Season`, `Episode`, `Genre`, `Coverage`; `Freshness` and
   `FRESH_FOR` (7 days); injectable `Clock`. SQLite: `read` (3 queries),
   `read_episodes`, `save` (one transaction: media fields, genre set, season
   summaries, dropped seasons), `save_episodes` (one transaction per season:
   remove unlisted, upsert listed, record coverage).
3. **TMDB** (`src/tmdb.rs`): `details(token, media_type, id)` for
   `/3/movie/{id}` and `/3/tv/{id}`, `season_episodes(token, id, n)` for
   `/3/tv/{id}/season/{n}`; private DTOs; blank strings, invalid dates,
   zero/negative runtimes and counts become "absent"; duplicate season
   numbers, episode numbers and episode ids are reduced to one; no
   `append_to_response`; `en-US`.
4. **Detail controller** (`src/detail.rs`): cache-first loading; the
   freshness policy after a 300 ms settle delay; background requests on the
   R7 worker pool; commit, re-read, re-render; Refresh (always asks) and Try
   again for a season; title and season generations against late answers;
   non-destructive notices for every failure; 404 never deletes.
5. **UI** (`ui/app-window.slint`): the production Library gets a
   `MediaDetailPane` (420 px): poster, title, original title, type and year,
   tagline, **Refresh**, **Remove**, "Updated …" / "Refreshing from TMDB…",
   notice, facts (only those TMDB gave), overview; for series a season list
   with coverage labels, the selected season's air date, episode count and
   overview, and a virtualized episode list (number, name, air date, runtime;
   the selected episode shows its overview). Season states: loading, not
   downloaded (with/without token), not available + Try again, no episodes,
   cached list + refresh-failure notice. Discover's preview and the benchmark
   fixture keep the R8 `DetailPane`.
6. **Token sharing** (`secrets::SharedToken`): `remote` publishes the token in
   use and fires `token-changed` when one appears or goes away; the detail pane
   then applies the policy to what is on screen.
7. **Keyboard/focus**: seasons (Up/Down/Home/End) and episodes
   (Up/Down/PageUp/PageDown/Home/End) are focus scopes in the Tab order after
   Refresh and Remove; focus is not trapped. **Switching sidebar pages now
   moves focus into the Library or Discover list** (the R8 gap).
8. **Diagnostics**: one line per settled selection (cache hit: fresh / stale /
   never fetched), one per detail or season request (outcome and duration),
   one per late answer not shown, and save failures. No bodies, no tokens.
9. **Docs**: ADR-0013–0015, README (details, schema v2, keyboard, layout,
   diagnostics, not-implemented list), this file; smoke script expects schema
   version 2.

## Behavior details

- **Cache first**: SQLite read + render happen synchronously on selection;
  requests start only afterwards, so cached content is always on screen first
  and never blanked.
- **Refresh policy** (ADR-0013): never fetched → request; ≤ 7 days → no
  request; > 7 days → background request; Refresh → always; no token → no
  request, "Connect TMDB in Settings to refresh".
- **Transactions** (ADR-0014): detail refresh = media + genres + season
  summaries in one transaction; each season's episodes in its own.
- **Reconciliation**: targeted upserts; grown seasons keep their rows; shrunk
  or renumbered seasons lose only unlisted rows; dropped seasons go; empty
  answers delete nothing; a detail refresh never touches episode coverage or
  library membership.
- **Coverage vs freshness** (ADR-0015): `details_fetched_at` vs
  `episodes_fetched_at` + `episodes_known` vs `episode_count` →
  Not downloaded / Partial / Complete.
- **Season 0**: stored, listed first as "Specials", fetched like any season;
  whether it counts toward completion is left to R10.
- **TV loading**: series detail stores summaries only; only the season on
  screen is fetched (first regular season by default): at most two requests
  per series open.
- **Artwork**: poster-first; the cached `w185` poster at 100×150 through the
  existing service. Backdrop paths are stored, never downloaded. No new image
  size or cache.
- **Errors**: offline/timeout, rejected token, rate limit, 404, server error,
  malformed answer and save failure each have a message; with or without a
  full detail cache, the pane keeps what it has and offers Refresh/Try again.

## Offline behavior (verified by `detail::tests::details_seasons_and_episodes_work_offline_after_one_fetch`)

Session 1 (fake TMDB online, file database): a movie and a series in the
library; opening the movie fetches its detail; opening the series fetches its
detail and season 1 — exactly three API requests. Session 2 (TMDB unreachable,
same file, clock one hour later): the movie shows tagline and four facts, the
series its three seasons and season 1's three episodes, with no request. Clock
past seven days: both refresh attempts fail, the pane keeps everything and
says "Can't reach TMDB. Showing the details saved on this computer."; the
season shows "Showing saved episodes." The fake server saw no request from
session 2.

## Local performance (informal, not `BENCHMARK_SPEC.md`)

`cargo test --release informal_detail_timings -- --ignored --nocapture`,
file-backed database with a 60-season series of 250 episodes each, medians:
read movie detail 0.102 ms; read series detail with 60 seasons 0.193 ms; read
one 250-episode season 0.250 ms; two season switches 0.518 ms; save movie
detail 4.324 ms; save series detail with 60 seasons 5.332 ms; save 250
episodes 9.134 ms (commits dominated by the disk sync). No N+1 queries (detail
read is three statements whatever the season count); no eager season fetch;
network and decoding off the UI thread; the episode list is a virtualized
`ListView`; facts, seasons and episodes models are rebuilt per render (small,
render only on selection/answer/poster). Release executable 24,971,264 bytes
(R8: 23,316,480).

## Known limitations

- A returning series can be up to seven days stale without Refresh; no
  per-status intervals.
- Only seasons that were opened have episodes offline; there is no "download
  all seasons" action.
- Detail and episode commits run on the UI thread (4–9 ms informally).
- `w185` poster only; soft at high DPI; backdrops not shown.
- A 404 is shown per session only; it is not persisted.
- The same title reselected before its first answer arrives may send a second
  request (bounded by user actions).
- A Discover re-add refreshes search fields but does not re-render an open
  detail pane until it is reselected.
- Genre rows, like orphaned metadata and posters, are never garbage-collected.
- Tests use real sleeps only where a fake server's latency is simulated;
  freshness uses the fake clock.
- macOS/Linux verified by CI only once pushed.

## R10 prerequisites now available

- Stable episode keys: (local series id, season number, episode number) plus
  the TMDB episode id, with no duplicate rows after refreshes.
- Season rows with `episode_count` and explicit coverage, independent of
  series freshness, so progress can be computed against a known denominator
  and new episodes are visible as partial coverage.
- Season 0 stored and labelled, with the completion policy still open.
- A personal-state firewall: refresh writes only provider tables; personal
  tables must be separate and must not cascade from `seasons`/`episodes`
  (ADR-0014).
- Movie runtime and episode runtimes for future statistics; air dates for a
  future calendar.
- The detail pane, season and episode lists, and focus handling ready to host
  watched controls.
