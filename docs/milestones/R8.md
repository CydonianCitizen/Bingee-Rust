## Implemented

1. **Schema.** v1 unchanged: it already has every field R8 persists. No v2
   migration; existing R6/R7 databases open as they are.
2. **Add to Library** (`library::add`): one `BEGIN IMMEDIATE` transaction —
   find `media` through `external_refs (source, media_type, external_id)`,
   refresh the search-provided metadata (keeping stored values the result
   lacks, `metadata_updated_at` = now) or insert `media` + `external_refs`,
   then insert `library_entries` unless present. Any failure rolls back
   everything. Repeated adds are no-ops that keep the original `added_at`.
3. **Remove from Library** (`library::remove`): deletes the membership row
   only; metadata, identity and the cached poster stay. Re-adding reuses them.
4. **Library data access** (`src/library.rs`): `search` (text + Movie/TV
   filter + sort by recently added or title, Unicode case folding, local id as
   tiebreaker), `count`, `add`, `remove`, `membership` (one query per result
   set via `json_each`). All parameterized; the only formatted SQL fragment
   is one of two constant `ORDER BY` clauses.
5. **Library page**: search, **All / Movies / TV**, a sort menu, posters,
   **Remove from Library** in the detail pane; empty, no-match ("No titles of
   this type…") and database-error states. The benchmark fixture hides the
   new controls, so its R4 layout is unchanged.
6. **Discover membership**: rows show **In Library**; the preview shows **Add
   to Library** or a disabled **In Library**. Membership is re-read from
   SQLite after each result-set change, add, or Library removal — never
   claimed before the transaction commits. A failed add keeps the results and
   shows why.
7. **Posters** (`src/poster.rs`): validated TMDB path → key
   `tmdb-w185-<stem>.<ext>`; RAM (12 MiB LRU of decoded RGB8) → disk
   (`<cache>/posters/`) → HTTP (`w185`, no token) on the worker pool; decode
   and size check before a temp file is synced and renamed into place; stale
   temp files removed at startup; one transfer per key however many rows ask;
   404/undecodable not retried, transient failures retried after 60 s, first
   failure per key logged; a damaged cache file is replaced; rows pull images
   by key, so a late poster cannot land on a recycled row.
8. **Image configuration**: TMDB's documented base until `/3/configuration`
   answers once per session after the token checks out; nothing that opens
   the library waits for it.
9. **Keyboard**: Discover list gets Up/Down/PageUp/PageDown/Home/End and
   Enter to add; Down/Enter in its search field focuses the list. Library
   filters, sort menu and the detail button are Tab-reachable.
10. **Diagnostics**: library add (identity, added or already there) and
    failures, remove, the first failure of each poster, one poster statistics
    line at exit. No per-hit logging, no secrets.
11. **Dependencies**: `image` 0.25.10 moved from dev- to runtime dependency
    (features `jpeg`, `png`) — Slint already linked it with exactly these
    features; `Cargo.lock` unchanged, no new crate.

  → network with one download for three simultaneous requests and a disk hit
  in a new session, corrupt/truncated/503/404 failures leave nothing on disk
  and are not retried at once, a damaged cache file is replaced, RAM-only
  mode.

  Discover by keyboard (click to focus, Down, Enter adds, End).
- `main` (2): a late poster never lands on a row that now shows another title
  (and not in the detail pane); a 1,000-title library loads only visible
  posters (9 for the first screen) and stays within the RAM budget during a

add also pays a disk sync per commit (not measured). The layout fix found by
the 1,000-title test: the new header controls stretched vertically and hid
half the list until their row got a fixed height.

## Known limitations

- Title sort is case-folded code point order: accented initials sort after Z.
- Orphaned metadata and poster files accumulate after removals (no GC yet).
- `w185` only: the detail poster is slightly soft on 200 % displays.
- Discover's Enter adds without confirmation; there is no undo for Remove
  (re-add restores the title with a new `added_at`).
- Two running instances share one database; writes rely on SQLite locking.
- macOS/Linux verified by CI build/tests only once pushed; Windows ran locally.

## R9 prerequisites now available

- Every library title has a `media` row with its TMDB identity in
  `external_refs`, ready for `/3/movie/{id}` and `/3/tv/{id}` detail fetches
  that can fill `runtime_minutes`, `backdrop_path` and refresh
  `metadata_updated_at`.
- `library_entries` is separate from `media`, so watch history can reference
  `media` and survive removals.
- The poster service, worker pool and image configuration are ready for
  larger variants or backdrops.
- `library::add`'s upsert rules (never erase with missing values) are the
  starting point for a refresh policy.
