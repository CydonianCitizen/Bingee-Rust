# R6 — Production foundations

This file records R6 as implemented (unattended session, 14 September 2026).
The decisions are in `docs/adr/0006-production-storage-and-schema-v1.md`.

**Status: PASS locally / cross-platform CI pending.** Every criterion was
verified on Windows. macOS and Linux are covered by unit tests of their path
policies and by the CI workflow, which has not run on this change (this
session cannot commit or push).

## Goal

Turn the R0–R5 benchmark spike into the production foundation of Bingee
Desktop: an empty real library in the right per-user folders, a versioned
schema with safe migrations, coherent errors and diagnostics, and correct
About/licensing, while keeping the R4 workload reproducible. No TMDB.

## Implemented

1. **Production vs benchmark.** The generator, spike schema, poster cache and
   their tests moved to `src/fixture/` unchanged in behavior. They compile
   only for tests and the `benchmark-fixture` Cargo feature
   (`r4-measurement` implies it), and run only with `--benchmark-fixture`.
   A default build contains no fake data and refuses that flag (exit 1).
   The fixture keeps the R5 paths beside the executable.
2. **Data paths** (`src/paths.rs`): `%LOCALAPPDATA%\Bingee Desktop\{data,
   cache,logs}` on Windows; `~/Library/{Application Support,Caches,Logs}/Bingee
   Desktop` on macOS; `$XDG_DATA_HOME`, `$XDG_CACHE_HOME`, `$XDG_STATE_HOME`
   (with the XDG defaults) plus `bingee-desktop` on Linux. `BINGEE_HOME`
   overrides all three. Relative values are rejected or ignored, so the
   working directory never matters. `std` only.
3. **Database** (`src/database.rs`): one owned `Database` (no global, no
   pool): open, `foreign_keys = ON` (verified), Unicode case-fold SQL function
   for search, migrations, `schema_version()`. Schema v1: `media`,
   `external_refs` (key `(source, media_type, external_id)`, type-checked
   composite foreign key), `library_entries`. All pending migrations run in
   one `BEGIN IMMEDIATE` transaction. Damaged, foreign (including the spike's
   `bingee-spike.db`), and newer files are refused without writing.
4. **Library** (`src/library.rs`, `src/view.rs`): the list and detail pane now
   read `library_entries ⋈ media`. The `slint::Model` view is shared by the
   production library and the fixture through a small `Library` trait. Rows
   without progress or poster show the placeholder and hide the progress UI.
5. **Errors** (`src/error.rs`): `AppError` = kind (database, filesystem,
   configuration, network (reserved), invalid data, internal) + a user-safe
   message + the low-level cause, which only reaches the log.
6. **Startup failure UX:** if the database cannot be opened or migrated, the
   window shows "Your library could not be opened" with the reason, the
   database and log paths (selectable), **Try again** and **Quit**. Nothing is
   deleted or recreated. Settings and About stay reachable.
7. **Diagnostics** (`src/diagnostics.rs`): `<logs>/bingee-desktop.log`, UTC
   timestamps, echoed to stderr. Startup (version, OS, architecture),
   database path, migration start/end, schema version and title count,
   failures, panics (hook), close. Rotated to `.log.1` above 1 MiB. No
   telemetry, no per-interaction logging, no secrets.
8. **Identity:** `APP_NAME = "Bingee Desktop"`; `APP_ID` and `APP_VERSION`
   come from Cargo (`bingee-desktop`, `0.1.0`). The window title, About, the
   Linux app id and the log name use them. No version string is duplicated.
9. **Shell:** the sidebar navigates Home, Library, Discover, Calendar,
   Statistics, Settings and About. Library, Settings and About are
   functional; the others are labelled placeholders. The detail pane shows
   only on Library. Empty library: "Your library is empty / Search for a movie
   or TV series to get started." (search field disabled).
10. **About:** name, version, Rust/Slint/SQLite credits, the `AboutSlint`
    widget, the Slint Royalty-free 2.0 basis, "license not decided yet",
    `THIRD_PARTY_NOTICES.txt`, and the data, cache, log and database paths
    plus schema version. It is a top-level sidebar entry, which meets the
    Slint attribution condition (a).
11. **Settings** (`src/settings.rs`): `Settings` holds Bingee's own
    configuration. R6 has exactly one setting, the `BINGEE_HOME` override.
    Future preferences become typed fields, persisted by the migration that
    introduces the first one. No settings table exists yet (none needed).
12. **Scripts and CI:** the Windows package no longer ships posters or
    `data/`; the smoke test checks fresh, second and corrupt-database starts
    with a redirected `LOCALAPPDATA`. `r4-core.ps1` and `r3-memory.ps1` now
    build/launch the fixture explicitly, so they fail instead of measuring an
    empty library. CI adds clippy for the default and fixture-only feature
    sets.

## Not done / out of scope

TMDB and any network access, adding titles (so the production library stays
empty in R6), posters for real titles, persisted preferences, watch progress,
seasons/episodes, backup/restore, a single-instance guard, WAL mode, an
installer or signing, bundled full license texts, macOS/Linux runtime checks.

## Exit criteria

| Criterion | Result |
| --- | --- |
| Production startup contains no fake library data | **Met.** Fixture code is not compiled into a default build; the smoke test logs "0 titles" |
| Correct cross-platform user-data paths | **Met** on Windows (smoke test); macOS/Linux policies unit-tested only |
| Schema v1 explicit and migrated transactionally | **Met.** Rollback test: a failing step leaves version and bytes unchanged |
| Movie/TV external-id collision impossible by schema | **Met.** Primary key includes `media_type`; tests |
| Startup DB failure not silently destructive | **Met.** Tests and smoke test: file byte-identical, error page, log entry |
| Benchmark fixtures reproducible and separate | **Met.** Byte-identical seeded database, R4 harness runs, separate paths |
| About/attribution accessible | **Met.** Sidebar → About with `AboutSlint` |
| Build/tests/clippy pass | **Met** (table above) |
| Documentation matches behavior | **Met.** README, ADR-0006, this file, notices |
