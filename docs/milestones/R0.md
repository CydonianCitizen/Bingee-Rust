# R0 — Bootstrap + visible desktop shell

Invoke with `/milestone R0`.

## Goal

The smallest clean Rust + Slint desktop application that is already visibly
recognizable as **Bingee Desktop** and runs with `cargo run`.

## Scope

### Left — navigation sidebar

Entries: Home, Library, Discover, Calendar, Statistics, Settings.
Only `Library` needs to appear selected. No real navigation yet.

### Center — library pane

A small deterministic fake library, 8–12 items mixing Movie and TV, supplied
from Rust through an explicit model boundary — not duplicated as static markup
in repeated Slint widgets.

Suggested titles (equivalent sample records are fine): Severance, Dark,
Dune: Part Two, The Bear, Arrival, Shōgun, Blade Runner 2049, The Last of Us.

Each row or card shows enough to make the layout useful: title, year, Movie/TV
label, and optionally lightweight progress or rating text.

No poster downloads. Use a cheap local placeholder (shape, gradient, or
initials) that adds no image dependency.

### Right — detail pane

Title, type and year, a short fake overview, simple progress or status.

Selecting an item in the center pane updates the detail pane if that is
straightforward in Slint. If selection would require disproportionate
architecture for R0, keep one deterministic selected item and document the
limitation. Do not introduce a framework to satisfy this.

## Visual direction

A desktop shell, not a mobile screen stretched horizontally: wide default
window, persistent sidebar, expanding center content, stable right pane,
restrained dark UI, clear spacing and hierarchy, no elaborate animation.

This is not the milestone for a design system. Aim for a credible, functional
shell.

## Structure

```text
Cargo.toml   Cargo.lock   build.rs
src/main.rs
ui/app-window.slint
README.md
```

Add modules only when they contain real code. Use Slint's recommended Rust
build workflow, and prefer the latest stable mutually compatible Rust and Slint
versions available in the environment. Record the exact resolved versions in
the report.

## Out of scope

TMDB, HTTP, API keys, remote images, SQLite, search, the 1,000-item dataset,
real poster loading, caching, notifications, backup/restore, Android sync,
production packaging, benchmark conclusions. No network access at runtime.

Do not add Tokio, reqwest, an ORM, an image crate, a logging framework, or a DI
framework: R0 needs none of them.

## Windows

Follow current Slint guidance for desktop executable and console behavior only
if it is actually needed. No speculative platform configuration.

## Documentation

Update `README.md` with prerequisites, how to run, how to run checks, current
R0 scope, and an explicit note that SQLite, TMDB, poster loading, and
benchmarking are not implemented. Document the Slint licensing assumption for
the spike only, without implying the product license has been chosen.

## Exit criteria

- `cargo run` opens Bingee Desktop.
- The `/check-rust` suite passes.
- The app is visibly desktop-first.
- No unnecessary dependencies.
