## Implemented

1. **Schema v3** (`database::SCHEMA_V3`, appended; v1/v2 untouched):
   `media_tracking (local_media_id, media_type, watched_at, rating 1–10)`,
   `episode_tracking (series, season, episode number, watched_at)`,
   `watch_events (event_id AUTOINCREMENT, local_media_id, media_type,
   season_number, episode_number, watched_at)` with time and media indexes.
   All reference `media (local_media_id, media_type)` with `ON DELETE
   RESTRICT`; none references `seasons`/`episodes`. Type rules as CHECKs.
2. **Domain** (`src/tracking.rs`, no Slint, no network): `watch_movie`
   (idempotent, or `again`), `unwatch_movie`, `set_rating`, `watch_episode`
   (idempotent, or `again`), `unwatch_episode`, `watch_season` /
   `unwatch_season` (one transaction, set-based SQL), `watched_episodes`,
   `series_progress` / `library_status` (one aggregate query), `next_episode`,
   `continue_watching` (domain only), `recent_history`, `delete_event`,
   `local_time`.
3. **Detail pane** (`src/detail.rs`, `ui/app-window.slint`): a boxed "Your
   tracking" (movie: Mark as watched / Mark unwatched, Watch again, watched
   date in local time) or "Your progress" (series: progress line and bar, next
   episode, specials) section with a 1–10 rating menu, separate from the TMDB
   header and Refresh. Episode rows get a watched mark (click, Space or
   Enter). The season heading row shows "2 / 6 watched" with **Mark season
   watched** and **Unmark**. Season list rows add "10 / 10 watched".
4. **Library rows** (`src/view.rs`): "Watched" for movies; "1 / 4 · 25%",
   "2 / 2 known · incomplete" or "Watched · 2 / 2" for started series, with a
   bar. Status for every library title is one query, re-read only when data
   changes (not per keystroke of the search).
5. **History page** (`src/history.rs`, sidebar entry): 200 most recent watches,
   newest first, title, "S1 E2 · name" / "Specials E3" / "Movie", local date
   and time; keyboard navigation, **Remove from history** / Delete.
6. **Smoke script** expects schema version 3.

## Rules (summary; details in the ADRs)

- **Firewall**: only `tracking.rs` writes personal tables; provider code and
  DTOs have no personal fields. Refresh, 404, episode/season removal and
  library remove/re-add cannot touch personal rows (schema and tests).
- **Removed provider episodes**: personal rows are kept; they count nowhere
  and show in history by number; if TMDB lists the episode again it is watched
  again.
- **Watched semantics**: mark = set state + one event only if it changed;
  unmark = clear state, keep events; watch again = new event, moves
  `watched_at`; delete event = event only.
- **Rating**: 1–10 integer or none, any title, independent of watched, never
  TMDB's score.
- **Timestamps**: Unix seconds UTC from the injectable `Clock`; local time via
  SQLite `localtime` for display only.
- **Specials**: trackable, excluded from main progress, completion and next
  episode; shown as "x / y specials watched".
- **Progress**: watched / stored regular episodes (never TMDB's count as the
  denominator). Percentage only with complete coverage; otherwise "downloaded
  episodes watched · episode list incomplete".
- **Complete** = details fetched, every regular season covered (ADR-0015),
  known > 0, all watched. `NextEpisode` distinguishes `Episode`, `Complete`,
  `CaughtUp` (all known watched, coverage incomplete) and `NothingKnown`.
- **Errors**: a failed write rolls back, logs one line (never what was
  watched), shows "Your change could not be saved…" and re-renders the
  committed state (including the rating menu).
- **Privacy**: nothing personal is sent anywhere or logged.

## Write threading and performance (informal, not `BENCHMARK_SPEC.md`)

Release build, file-backed database, Windows 11 (ADR-0019 has the tables).
End to end on the UI thread with a 1,000-title library: episode toggle median
9.96 ms (max 12.2 over 100 rapid clicks), 250-episode season watched 21.4 ms,
movie toggle 9.56 ms, rating 8.25 ms. SQL alone: one episode commit 4.9 ms;
250-episode season 7.2 / 5.8 ms; 2,000-episode season 11.7 / 7.8 ms; progress
of 61 seasons / 17,000 episodes 4.3 ms; next episode 0.06 ms; library status
for 1,000 titles 5.3 ms; 200 recent of 33,099 events 0.55 ms. **Decision:
writes stay synchronous** — about one frame per action, one to two for a
whole season, no accumulation under rapid clicks; a worker would add ordering
and pending-state complexity without evidence of stalls. No N+1: progress and
library status are single aggregate statements, next episode reads one season.

Release executable 25,959,424 bytes (R9: 24,971,264).

## Known limitations

- Episodes of seasons never opened are unknown, so such a series reads as
  "episode list incomplete" until those seasons are downloaded.
- Episode renumbering by TMDB leaves watched state on the old number.
- No UI for episode rewatches or for choosing a past watch date; bulk season
  marks share one timestamp.
- History shows the 200 most recent watches only; it reloads when the page
  opens.
- Personal writes run on the UI thread (~10 ms; ~21 ms for a large season).
- After each personal change the Library's status for all titles is re-read
  (5 ms at 1,000 titles).
- Unaired known episodes can be marked watched and are included in season
  bulk marks.
- `continue_watching` has no UI yet.
- macOS/Linux verified by CI only once pushed.
