# R14 — Metadata refresh and release events

R14 adds opt-in, in-app metadata maintenance. The local UI starts first.
When enabled and a TMDB token is available, a coordinator checks stale
Library metadata after startup and every six hours while Bingee is open.
It reuses R9's seven-day freshness rule, selects at most 50 titles and 50
previously downloaded seasons per cycle, and sends only one automatic HTTP
request at a time through the existing four-worker pool. Fresh titles and
unopened seasons are skipped. Changed counts of already downloaded seasons
can enqueue one season fetch. Removed titles are ignored, including when
membership changes during a request.

Rate limits pause maintenance for 30 minutes; offline, timeout and server
failures pause it for 15 minutes. Invalid credentials stop it until credential
state changes and prompt the existing Settings check. Nothing is deleted on
network failure. There is no daemon, startup registration, or OS notification.

Schema v5 stores the automatic-refresh preference (default off) and release
events. An event is inserted only when a previously downloaded Library season
gains a new episode number. The unique key prevents repeated events. Events
survive restart, retain read state, and appear in the local Updates page.
Opening one marks it read and navigates to its episode; Mark all read is
also available. Home and Calendar reload after metadata saves. Metadata
refresh never writes tracking, ratings, history, membership, or event read
state. Backup V1 now includes the preference and release events.

Decisions: ADR-0026 and ADR-0027. Exact test, performance and package results
are recorded in this session's `docs/run-reports/` report.
