## Implemented

1. **Schema v4** (`database::SCHEMA_V4`, appended; v1–v3 untouched):
   `watch_events.runtime_minutes` (CHECK > 0), backfilled from stored movie /
   episode runtimes, `NULL` when unknown. `tracking` inserts copy the runtime
   in the same statement (movie, episode, whole season).
2. **Domain** (`src/statistics.rs`, no Slint, no network): `load(db, range,
   now)` → `Statistics { movies, episodes: Viewing, activity: Vec<Bucket>,
   genres: Vec<GenreCount>, library: LibraryNow, has_history }` in 6–7 SQL
   statements. `LibraryNow` reuses `tracking::library_status` for completion.
3. **Page** (`src/statistics_page.rs`, `ui/app-window.slint`): range buttons
   (30 days / 12 months / All time), "Viewing history" (watch time hero card
   with unknown-runtime note, watches, movie watches, episode watches,
   rewatches; watches-per-day/month/year column chart; Movies and TV split by
   known watch time; top 8 genres with a multi-genre note and "No genre
   stored"), "In your Library now" (average rating, movies watched x of y,
   episodes watched, series complete x of y; series progress bars with an
   incomplete-coverage note; 1–10 rating distribution). Native Slint
   rectangles only. Empty state, error state. Reloads on page open and range
   change.
4. **Smoke script** expects schema version 4. README, ADR-0020, ADR-0021.

## Semantics (summary; details in ADR-0020 / ADR-0021)

- History metrics come only from `watch_events`, whatever Library membership
  or watched state: unmark keeps them, History deletion removes them, Library
  removal keeps them.
- Current metrics cover titles in `library_entries` only.
- Rewatch = an event that is not its target's first recorded event (target =
  movie, or series + season + episode); the first may be before the range.
- Watch time = Σ runtime snapshot; a rewatch adds again; snapshot `NULL` →
  runtime stored now, else unknown and counted apart.
- Ranges: local calendar (30 days = today + 29 days; 12 months = this month +
  11; all time = yearly bars). Persisted timestamps stay UTC.
- Genres: current stored genres; episodes inherit the series'; each watch
  counts in every genre; no percentages.
- Ratings: rated Library titles only, one per title; average over rated.
- Complete = R10 `is_complete` (coverage-aware); specials excluded from
  progress, included in watches and watch time.

## Performance and threading (informal, not `BENCHMARK_SPEC.md`)

Release build, file database, Windows 11. Test-only synthetic history
(`statistics::tests::large_history`): 1,000 titles, 17,505 episodes, 10,000
watch events, 19 genres, 313 ratings, rewatches.

| Measure | Median |
| --- | --- |
| `load` 30 days / 12 months / all time | 18.0 / 22.0 / 21.9 ms |
| viewing totals / activity / genres / library now | 10.7 / 0.47 / 4.5 / 5.9 ms |
| Page end to end (query + view + software render 1280×800), choose 30 d / 12 m / all | 27.9 / 29.6 / 28.4 ms (max 31.7) |
| First open, cold statement cache, end to end | 46.9 ms |

Query plans (printed by the timing test with `R11_PLANS=1`) use primary keys
and `watch_events_by_time`; no per-event statements. The first query version
measured 58 ms; rewritten (per-target aggregate instead of a window with
`count(DISTINCT)`, genres aggregated per title, per-bucket index range counts
instead of `localtime` per event, runtime lookup only for events without a
snapshot). A candidate target index saved ~2.5 ms and was not added.
**Decision: synchronous on the UI thread** (ADR-0020).

Release executable 27,002,368 bytes (R10: 25,959,424).

## Known limitations

- Statistics load synchronously (~2 frames on a 10,000-event history).
- Genre changes from a TMDB refresh re-categorise past watches.
- Events recorded before v4 carry the runtime known at upgrade time.
- Statistics reload on page open or range change, not live while open (no
  personal action can happen on the Statistics page itself).
- Only watch events are charted (no watch-time chart toggle).
- Ratings and progress of titles removed from the Library are not shown.
- `IMPLEMENTATION_PLAN.md` still ends at "Next: R10" (not updated in R10 or
  R11).
- macOS/Linux verified by CI only once pushed.
