# R13 — Versioned backup and restore

R13 adds a typed JSON V1 contract (`docs/backup-v1.md`), complete pre-restore
validation, and replacement of durable data in one SQLite transaction.
Settings uses native cross-platform file dialogs. The restore button first
selects and validates a file, then requires a separate Confirm action.
Export writes a same-directory temporary file and creates the final name
through an atomic hard link. Existing backup files are never overwritten.
Before confirmed restore, Bingee exports a safety JSON copy beside its
database. Failure to create that copy stops the restore. The file remains
until the user removes it.

V1 includes offline media metadata, external identities, Library membership,
genres, seasons, episodes, independent freshness and coverage, personal
tracking, ratings, and history with runtime snapshots. Credentials, binary
cache, logs, fixtures, and diagnostics are excluded. Tests use an injected
dialog adapter; no interactive dialog opens during automated tests.
R14 extended V1 additively with automatic-refresh preference and release
events; earlier V1 backups remain accepted.

Decisions: ADR-0023, ADR-0024, ADR-0025. Exact verification and performance
results are in this session's report under `docs/run-reports/`.

Status: PASS locally. Cross-platform CI awaits a user commit/push.
