# R3 — Poster pipeline and bounded image cache

Invoke with `/milestone R3`. This file records the brief as it was
implemented. Decisions are in `docs/adr/0003-poster-pipeline-and-bounded-cache.md`,
and the numbers are in `docs/measurements/R3-posters-informal.md`.

## Goal

Add a representative local poster pipeline to the SQLite-backed library,
keep the UI responsive, and keep decoded-image memory explicitly bounded. Still
a technology spike: no TMDB and no networking.

It must answer:

- how Slint behaves with real raster images;
- whether ListView virtualization also avoids image work;
- how much decoded-image memory is needed;
- whether synchronous local loading is enough;
- whether a small explicit cache keeps RAM bounded during long scrolling.

## Implemented

1. **Benchmark assets:** 100 synthetic 240×360 baseline JPEGs (quality 85) in
   `benchmark/assets/posters/`, generated deterministically by
   `examples/generate_posters.rs`, with `SHA256SUMS` and a README for the
   Avalonia spike. They are not derived from any real poster.
2. **Poster identity:** poster number = `(local_id − 1) % 100 + 1`
   (`poster::poster_number`). `MediaItem` and the SQLite schema are unchanged.
   Decoded images exist only as `slint::Image` in the UI row data and in the
   cache.
3. **Lazy loading:** posters are requested from `Model::row_data`, so only for
   the rows the virtualized ListView instantiates, and for the detail row.
   Nothing is loaded at startup beyond the first frame's rows.
4. **Bounded cache:** `poster::PosterCache`, an LRU keyed by poster number,
   bounded by an estimated decoded size of `w × h × 4` bytes, with a budget of
   12 MiB (36 posters). It is shared by the rows and the detail pane and
   generic over the value type, so it can be unit-tested.
   - An image larger than the budget is returned but not cached.
   - A failed load is remembered, not retried, and logged once.
5. **Slint image path:** `slint::Image::load_from_path`. It decodes eagerly
   (with Slint's own `image`/`zune-jpeg`) into an RGB8 buffer. The cache holds
   `slint::Image`, a reference-counted handle to that buffer. When the last
   handle is dropped (cache, row data, and Slint's internal cache), the buffer
   is freed. No runtime image dependency was added.
6. **UI:**
   - Rows show a 40×60 poster thumbnail.
   - The detail pane shows a 160×240 poster from the same cached image.
   - A missing or corrupt poster shows the R2 gradient-and-initials
     placeholder.
   - F12 with the list focused prints the cache counters to stderr (debug aid,
     no polling).
7. **Threading:** synchronous on the UI thread, kept after measurement and
   direct observation. No Tokio, threads, or channels.
8. **Tests:**
   - cache unit tests: hit/miss, no re-decode on hit, LRU eviction, the
     budget invariant, the oversize and failure policies, and releasing
     evicted values;
   - id → poster mapping;
   - a missing/corrupt poster falls back to the placeholder;
   - a headless render of the real window (Slint software renderer) shows
     that startup loads only the visible posters, a model reset over the same
     rows costs zero loads, and a long scroll evicts within budget.
9. **Measurements:** release decode timings, a scripted memory observation
   with an R2 baseline (`benchmark/scripts/r3-memory.ps1`), an FPS run, and
   direct human observation of scrolling.

## Not done / out of scope

TMDB, HTTP, remote images, a disk cache, Tokio, schema changes, BLOBs, and
everything else listed as out of scope in the brief. Also not done: formal
Rust-vs-Avalonia comparison, and attribution of the non-cache memory growth
(R4).

## Exit criteria (`IMPLEMENTATION_PLAN.md`)

- Scrolling does not decode the whole poster set: **met**. The first frame
  loads 9 posters. Each screen loads only its own rows' posters.
- Memory does not grow without bound during repeated navigation: **met in
  informal observation**. The cache is bounded at ≤ 12 MiB (estimated), and
  process private bytes plateau at about 194 MiB over 4 passes / 5,000 loads.
- The same asset set can be used by the Avalonia spike: **met**. The assets
  are plain JPEGs with checksums and a documented mapping.
