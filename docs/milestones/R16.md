# R16 — Distribution and installers

Status: PARTIAL. Windows installer and portable ZIP built and tested locally. macOS and Linux package scripts and release workflow exist, but those artifacts have not run on their native runners. See `docs/run-reports/2026-09-30-r16-technical-gate.md`.

Cargo package version `0.1.0-rc.1` is the single version source. The installed application remains `Bingee Desktop`; the technical executable and Linux ID remain `bingee-desktop`. The macOS bundle ID is `io.github.cydoniancitizen.bingee-desktop`. Its numeric bundle version is derived from Cargo SemVer (`0.1.0-rc.1` becomes `10002`); About retains the full version. Windows Inno Setup uses a stable AppId and per-user installation. All application data stays in user directories, separate from install files.

Windows packaging makes an unsigned installer EXE, portable ZIP and directory. Inno Setup 6.7.3 is fetched from the official release, checked by SHA-256 and Authenticode, and installed portably under `target/tools/`. The installer was built locally. Isolated install, launch, reinstall and uninstall smoke passed; the schema v5 database survived uninstall. The portable package smoke also passed fresh, reopen, corrupt DB, second-instance contention and idle hard-kill recovery. The Microsoft Visual C++ 2015–2022 Redistributable (x64) is a documented prerequisite and is not bundled.

macOS packaging creates `Bingee Desktop.app`, an Info.plist, bundled notices/licenses and a tarball. Signing and notarization are not configured. Linux packaging creates an executable tarball with a desktop entry, icon and user-level install/uninstall scripts. Native build and runtime verification are pending.

Packages include generated per-crate license material and `THIRD_PARTY_NOTICES.txt`. Slint and TMDB attribution is present in About. `docs/release-licensing.md` separates engineering work from unresolved distribution decisions. The `release-artifacts` GitHub Actions workflow now runs on a push to `main` or manual dispatch. It builds, checks and uploads all three platform artifacts without publishing a release. It has not run for this working tree because commits and pushes are denied by `.claude/settings.json`.

The R16 **technical** gate requires successful native Windows, macOS and Linux package builds, package structure checks, and normal cross-platform build/tests. Signing and notarization can remain pending. The owner's license and intended-use decisions remain public-distribution blockers but do not block R17 technical validation once this gate passes.
