# R15 — Hardening and data hygiene

Status: PASS for the stated local exit gate; broader crash and live UI coverage remains partial. See `docs/run-reports/2026-09-29-r15-r17.md`.

An OS-backed file lock now owns the production profile before SQLite opens. A second process shows a startup message without opening the database. The lock file may remain after a crash; the OS lock releases. Windows package smoke exercised two live processes and restart after a hard kill.

Settings offers explicit integrity diagnostics and conservative cleanup. `quick_check` and `foreign_key_check` run on request, not every launch. Metadata cleanup excludes anything referenced by Library membership, ratings/movie tracking, episode tracking, watch events or release events. Poster cleanup preserves referenced and recently read files, ignores unknown files and symlinks, and removes old unreferenced cache and stale poster temporary files. Release-event rows remain indefinitely; Updates limits its display query.

Backup export still uses a hard link where available and falls back to exclusive create, copy and sync where unavailable. It never overwrites a destination. A truncated fallback copy fails JSON validation. Existing restore validation, safety copy, transaction, foreign-key and integrity checks remain. SQLite uses a DELETE rollback journal, FULL synchronous writes, foreign keys and a 5-second busy timeout. Runtime log rotation keeps one previous 1 MiB log.

Tests cover locking, stale file, cleanup preservation, cache age, both backup finalization paths, destination collision, copy failure, integrity checks and pragmas. The ignored large-data UI soak ran 100 cycles over 1,000 media, 17,550 episodes and 10,000+ watch events. Sampled resource use stayed near 50 MiB working set, 16 MiB private bytes, 191 handles and six to nine threads during the measured interval. The soak did not automate every detail/tracking action or crash during active metadata and backup writes.

Decision: ADR-0028.
