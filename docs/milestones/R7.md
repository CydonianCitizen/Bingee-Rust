## Implemented

1. **Secret storage** (`src/secrets.rs`). `Token` newtype: redacted `Debug`,
   no `Display`, UI shows `…` plus the last four characters. `SecretStore`
   trait (`load`, `save`, `delete`) with `KeyringStore` (keyring 4: Windows
   Credential Manager generic credential
   `tmdb-api-read-access-token.bingee-desktop`, macOS Keychain, Linux Secret
   Service) and an in-memory store for tests. Keyring errors keep only their
   `Display` text. No environment-variable override.
2. **Credential lifecycle** (`src/remote.rs`, Settings → TMDB). States: not
   connected, reading, checking, connected, rejected, can't reach TMDB, TMDB
   problem (rate limit/server/unreadable), secure storage unavailable. A pasted
   token (password field) is validated remotely and saved only if TMDB
   accepts it; a failed check never saves and never discards the saved token.
   Check again, replace, remove. At startup the saved token is read and checked
   in the background. Removing stops Discover at once and deletes the entry;
   the database is not touched.
3. **HTTP and execution** (`src/tmdb.rs`, `src/network.rs`). One `ureq`
   agent (rustls + ring, webpki-roots, gzip, connection pool) with a 10 s
   connect and 15 s whole-request timeout. A pool of 4 app-owned worker threads
   runs every network and credential-store call; results return to the UI
   thread through `slint::invoke_from_event_loop`. No async runtime.
4. **DTOs and mapping.** Private `MovieDto`/`TvDto`/`PageDto`/`AuthDto`
   (serde), mapped at once to `MediaSearchResult { external: ExternalRef
   { source, media_type, id }, title, original_title, release_date, overview,
   poster_path, backdrop_path }`. Empty strings become `None`, non-ISO dates
   are dropped, entries without id or title are skipped, `total_pages` is
   capped at 500. Nothing reaches Slint, the database or the domain unmapped.
5. **Discover** (`ui/app-window.slint`, `DiscoverPage`). Search field, result
   summary, virtualized list reusing the library rows (type · year · original
   title), preview in the detail pane, **Load more**, "Results from TMDB".
   States: no token (Open Settings), empty query, searching, results, no
   results, can't reach TMDB, rejected token (Open Settings), too many
   requests, TMDB problems, unreadable answer (Try again), and a notice when
   one type failed while the other has results.
6. **Search scope and order.** Each search queries movies and TV
   concurrently. The list interleaves them by position (movie 1, TV 1, movie
   2, …), a pure function of what has loaded, so arrival order never changes
   the final list. One type failing leaves the other intact; Load more retries
   the failed type. The top row is selected automatically; a row the user
   picks stays selected while it is listed.
7. **Debounce.** 300 ms. Each edit starts a new generation and a single-shot
   Slint timer; only the latest generation's timer sends. Whitespace-only
   queries send nothing; trailing whitespace is not a new query; clearing
   invalidates everything in flight.
8. **Stale responses.** Every request carries its generation and page; a
   response is applied only if both still match the pending request.
   In-flight requests are not cancelled; they finish and are dropped (logged
   as "stale, dropped").
9. **Pagination.** Page 1 of both types, then Load more fetches the next page
   of each type that has one (max 500 or `total_pages`). Duplicates are
   dropped by full identity. No prefetching.
10. **Errors.** `TmdbError`: `CredentialInvalid` (401), `RateLimited` (429),
    `Timeout`, `Offline` (DNS/connect/TLS/I/O), `Server` (5xx),
    `MalformedResponse`, `Unexpected`. Each has a user message; `Display` is
    diagnostic and token-free; `From<TmdbError> for AppError` keeps the R6
    kinds (Configuration, InvalidData, Network). No automatic retries.
11. **Posters.** Deferred. `poster_path`/`backdrop_path` are kept; rows show
    the existing placeholder. No image download, disk cache or decoded cache.
12. **Logging.** Token read/check/save/remove outcomes and one line per
    completed search request (generation, type, page, count or error
    category, duration). Never the token, the `Authorization` header or the
    query text.
13. **Attribution.** About shows the official TMDB logo (SVG, hash-verified)
    and "This product uses the TMDB API but is not endorsed or certified by
    TMDB". `THIRD_PARTY_NOTICES.txt` records the logo and the new crates.
14. **Fixture isolation.** The benchmark fixture does not start the network
    pool, the credential store or TMDB; its Discover and TMDB settings say
    "Not available in the benchmark fixture".

  with the same numeric id, page cap, token redaction in `Debug`, `Display`
  and `AppError`, `AppError` kinds.
- `secrets` (4): redaction, parsing, keyring error text, memory store.
- `network` (1): jobs run concurrently off the calling thread and post back.
- `remote` (5), the real Slint window headless with a controllable clock,
  the real worker pool and the fake server: debounce with the Slint timer,
  a slow older search answering after a newer one is dropped, Load more and
  selection; token lifecycle (rejected not saved, accepted saved and field
  cleared, rejected replacement keeps the saved token, removal); revoked token
  in Settings and Discover; unavailable credential store; offline Discover
  while the library keeps working, the UI thread answers a library search
  in under 500 ms during a pending network call, and the database file stays
  byte-identical.

## Known limitations

- Live TMDB never contacted in this session; field names follow the official
  reference and are covered by fixtures only.
- macOS Keychain and Linux Secret Service paths are build-checked by CI
  only. Linux without a Secret Service cannot save a token (by design, no
  plaintext fallback).
- `webpki-roots` ignores OS-installed root certificates (TLS-inspecting
  proxies fail as "can't reach TMDB").
- Superseded requests are not cancelled; they occupy a worker for at most
  15 s.
- English metadata only (`en-US`); no language setting.
- Discover has no keyboard navigation in its list (mouse selection; Esc
  clears the search); no posters.
- The token lives in ordinary process memory while the app runs.
